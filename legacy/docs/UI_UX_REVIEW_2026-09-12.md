## 已完成的兩項修正

1. Chat／資料查找模型測試，現在會保留實際收到的 HTTP 狀態碼，並在卡片主區顯示中英文原因與下一步。例如 HTTP 402 提醒檢查服務商餘額或方案，HTTP 503 提醒稍後重試／查看服務狀態。逾時、無法連線、格式錯誤分別處理，不猜測不存在的 HTTP 回應。
2. 兩種模型的新增按鈕統一為「新增模型 / Add model」。

根因有兩層：provider adapter 原先把 HTTP 狀態轉成類別時丟失數字；profile probe 又把例外統一存成 `CHAT_PROBE_FAILED`／`EMBEDDING_PROBE_FAILED`。本次在 adapter 保留經驗證的數字，以既有 `last_error_code` 儲存安全診斷，前端共同翻譯。沒有資料庫遷移；沒有改公開 API 的 HTTP 狀態、模型選用或自動切換行為。

重新讀取仍可看見失敗原因；成功重試會清除舊錯誤。測試失敗時保留使用中的設定。只保留數字與固定分類，不保留或顯示服務商原始回應、API key、私有網址、headers 或例外文字。

**既有的泛用失敗紀錄無法還原已丟失的狀態碼，須由使用者再按一次測試。執行中的 Python 服務也須重新啟動才會載入後端修正。** 本輪沒有呼叫擁有者的模型、改動實際設定或重啟既有服務。

## 12 項額外問題，待決定方向

### 01．測試成功、可用於分析，卡片卻說「需確認相容性」

**優先：高；瀏覽器及程式確認。** `EmbeddingProfilePanel.tsx:268` 把 `reindex_required` 歸為「需確認相容性」，但 `AnalysisSelectionPanel.tsx:42` 允許成功測試的相同狀態用於分析。在進階模式，啟用按鈕又只接受 `ready`；`operations.py:303` 的公開啟用路徑原本能排入重建工作，UI 可能先擋住入口。

建議：卡片主狀態改「測試通過，可用於分析」；另列公開網站狀態「需建立／重建索引」，對應「建立索引並啟用」操作。涉及重建入口時仍保留明確動作與原有檢查。較小方案只調整卡片文案，但會留下進階入口問題。

### 02．資料查找模型無法在 UI 編輯

**優先：高；瀏覽器及程式確認。** `EmbeddingProfilePanel.tsx:47` 的 props 與卡片沒有更新／編輯操作；後端 `embedding_profiles.py:334` 已有 update。模型名稱、維度填錯時，只能刪除再新增；原先還顯示「可編輯後重試」。本輪錯誤文案已移除此錯誤承諾，編輯能力仍待實作。

建議：補上與回答模型一致的編輯表單，沿用既有更新 API，更新後重新測試。使用中的公開模型仍依現有規則保護。較小方案提供「以此設定新增」保留原設定，但不能取代完整更新流程。

### 03．新增資料查找模型，先要求使用者知道「維度」

**優先：高；程式確認。** `EmbeddingProfilePanel.tsx` 的 `embedding-profile-dimension` 是必填主欄位；沒有預設值或取得維度的引導。規格 11.5 已要求維度等技術資訊放進階，未知維度透過實際取樣取得。現在不知道模型維度就無法完成新增，任填數字又只會造成測試失敗。

建議：先填服務與模型，明確按測試後取得維度，將前綴／維度留在進階確認。這需要完整處理未知維度的 request／資料狀態，不能只把必填欄位藏起來。備選為先提供可核實的維度提示與說明，但只是過渡方案。

### 04．步驟編號與實際順序相反；手機仍提示「左側／右側」

**優先：中；瀏覽器及程式確認。** `ModelSetupWorkspace.tsx:53` 把選用列為步驟 1，文字卻說要先完成右側測試。回答／查找列為 2、3，內部又各有 1、2。`styles.css:1392` 在窄螢幕重排選用區，但左右方位文字沒有變。

建議：三個區塊不編號，改為「回答模型」「資料查找模型」「確認分析模型」；只在實際操作序列標「新增 → 測試 → 選用」。文案用區塊名稱定位。備選是把確認選用固定放最後並重編順序。

### 05．同一模型接不同服務，選用清單無法分辨

**優先：中；瀏覽器確認。** `AnalysisSelectionPanel.tsx:99`／119 的 option 只顯示 `model_id`。兩個服務都提供同一模型時，清單出現兩個完全相同的名稱，卡片上的服務資訊沒有帶入。

建議：選項統一為「模型名稱 · 服務名稱」，同一服務內仍重複才補短設定識別。不要顯示私有 URL。

### 06．「已選用」提示與使用者正在修改的選項不同步

**優先：高；程式確認。** `AnalysisSelectionPanel.tsx:140` 只依最後儲存的 `value.eligible` 顯示成功。改選但未確認，仍可看到「兩個模型已選用」。同檔 53–72 的同步及按鈕判斷只檢查 ID 非空，可能留下已不在可選清單內的儲存 ID。後端的 `reason` 已能指出未測試／版本變更，畫面卻統一說「請分別測試並選擇兩個模型」。

建議：區分「目前生效」及「修改尚未確認」，確認前驗證兩個 ID 都仍在有效清單內，並翻譯伺服器原因。服務版本過期時直接導向更新該模型設定與重測，不能只讓使用者反覆按測試。

### 07．「選擇服務」區只有編輯／刪除；修改名稱又要求重填 API 位址

**優先：中；瀏覽器及程式確認。** `ModelConnectionPanel.tsx:48` 要使用者選擇連線，但服務卡片沒有選取動作，真正的選單在新增模型表單。`edit()` 在 179 行清空網址，網址輸入又必填，因此只想改顯示名稱，也必須再次提供網址；未說明這是寫入專用欄位。

建議：區塊改「管理服務」，模型表單負責選擇；編輯時清楚說明網址不會回顯，區分「保留目前位址」與「更換位址」。後者需要相應更新契約與測試，不能用空白含糊代表兩種意圖。較小方案先改說明文字。

### 08．送出失敗／直接收起服務表單，新輸入的 key 仍留在表單狀態

**優先：高；程式確認，涉及既有隱私要求。** `ModelConnectionPanel.tsx:157` 送出 draft 後沒有清除 key；只有成功後 `onClose` 或取消等路徑才清除。`ModelEditor.tsx` 的原生 summary 收合也沒有呼叫 `onClose`。因此網路／驗證失敗後，或按標題直接收起後，輸入仍在元件內。這不代表已寫入瀏覽器儲存，但不符合 AC-055 的送出／退出後清除要求。

建議：保留非敏感的名稱與模型欄位，送出後即清除新 key；失敗後明確提示需要重填；所有取消／收合／登出／過期路徑一致。收合到底代表「取消」還是「稍後繼續」，可自行選擇，但敏感欄位都應清除。

### 09．未使用 Ollama 也顯示安裝清單；讀取失敗被顯示成「0」

**優先：中；瀏覽器及程式確認。** `EmbeddingProfilePanel.tsx:225` 永遠顯示「已安裝於設定的 Ollama host (0)」。`AdminPage.tsx:1119` 把讀取安裝清單失敗轉成空陣列。使用雲端服務時資訊多餘，Ollama 連不到時則把失敗誤報為未安裝。

建議：只有選取原生 Ollama 服務時顯示，區分「尚未讀取」「沒有模型」「讀取失敗」，提供針對此服務的重試。清單必須對應所選連線。

### 10．操作成功後刷新失敗，結果與表單狀態會不明確

**優先：中；程式確認。** `AdminPage.tsx:1747`／1785 沒有先採用測試回傳的 profile，而是再 GET 清單。若 POST 成功、GET 失敗，卡片保留舊資料。刷新函式自己控制與外層操作共用的 pending，且吞下刷新例外，可能提早顯示操作完成。部分一般失敗文字還要求「檢查安全狀態碼」卻沒附碼（同檔 516）。

建議：先用成功回傳更新對應卡片，再背景刷新；區分「操作失敗」與「已完成，但清單更新失敗」，提供重整而非再次送出。每張卡片標示目前測試中的模型與操作，清單讀取另有狀態。

### 11．一般引導文案仍大量露出內部資料類型

**優先：中；程式確認。** `GuidedOnboardingView.tsx:283` 起出現 `REPOSITORY_FACT`、`MODEL_INFERENCE`、`OWNER_ASSERTION`、`evidence`、`statement`；339 行出現 `validation/preview`。「Headline」翻成「標題」也不易判斷要填職業介紹還是作品標題。分析選單仍有 `Chat profile`，發布區仍有 `bundle`。

### 12．取消、新增空狀態與操作名稱不一致

**優先：中；程式／可及性樹確認。** Chat 表單取消會清空；Embedding 的 `ModelEditor` 沒有 `onClose`，收起後再開仍是舊資料，成功新增後也會保留欄位。沒有服務時 Chat 引導先新增服務，Embedding 卻仍顯示無可選服務的新增表單。多張卡片中的「編輯」「測試模型」又有相同的可及名稱。

## 如何避免再靠逐一截圖找問題

把同一套行為表套在服務、回答模型、資料查找模型、分析選用上：空資料 → 新增 → 保存 → 測試中 → 測試成功／401／402／429／503／逾時 → 重試 → 修改 → 版本失效 → 取消／刪除 → 重新整理。每一步都確認主提示、可用操作、資料保留與雙語一致。

現有多數元件測試是靜態 HTML 斷言，能擋住文案／結構回歸，較難抓到上述狀態轉換。後續批次應補少量真正操作表單、切換選項、模擬網路刷新失敗的互動測試，與此表對照；不用把每段文字都另寫一個測試。
