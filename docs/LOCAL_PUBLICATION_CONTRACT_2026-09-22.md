# Local portfolio publication contract

Status: Approved for implementation by the owner's 2026-09-22 instruction to implement the revised publishing plan using Luna Max, with Main review. This amendment (ADR-046) takes precedence over the older GitHub-only transport requirements in ADR-001/005/010/030, FR-019–021 and AC-026/029–032. Existing safety and evidence requirements remain in force.

## Owner journey

The six AI/four manual content steps remain. A validated character can be applied to the same portfolio draft. Completing content opens an ordinary preview/preparation/sharing surface. YAML is an optional backup, not the publication deliverable. Public GitHub repositories remain the source of project facts. Analysis, indexing, activation and query inference run on the owner-controlled host. GitHub Actions and write credentials are not required.

## Local state and boundaries

- `data/local-portfolio/draft.json` stores only validated public configuration and an optional canonical PNG, atomically replaced after validation. A SHA-256 revision binds configuration and asset bytes. Compare-and-swap rejects stale saves. It is private owner state until explicit preparation/activation. Existing immutable bundle storage remains the source served to visitors.
- Configuration is limited to the existing 1 MiB bound, canonical PNG input to the existing sprite validator bounds. No model URLs, keys, input archives or unconfirmed suggestions are persisted here. Save/read responses are authenticated and `no-store`.
- A bounded passage-vector cache under `data/passage-cache` contains content-addressed validated vectors only, never raw source/prompt text. The key includes complete embedding identity, a cache-format/preprocessing version and exact passage bytes. TTL is 30 days and total capacity 256 MiB, with oldest entries removed first. Corrupt, expired or incompatible entries are misses; no fallback provider. It is disposable and excluded from portable public exports. Full host backup may retain it; removal only causes necessary recomputation.
- The draft and validated bundles are included in an operator's stopped-service backup of the data directory. Public YAML backup excludes secrets and is not an index backup. Custom PNG must accompany a portable configuration.

## APIs and lifecycle

Existing owner session, origin, CSRF, private admin reachability and request bounds apply. New protected `/api/admin/portfolio` GET/PUT read/save the local draft (`content`, nullable `sprite_base64`, `expected_revision` for PUT; response includes `revision`). POST `/api/admin/portfolio/preview` renders the submitted validated public draft without model calls. POST `/api/admin/portfolio/prepare` freezes the saved revision and explicitly selected model pair, queues bounded local build and activation, and returns status; GET `/api/admin/portfolio/status` recovers progress; DELETE `/api/admin/portfolio/prepare` requests cancellation. POST `/api/admin/portfolio/character` validates canonical PNG and returns a rewritten draft without saving. POST `/api/admin/portfolio/github-profile` performs bounded anonymous GitHub metadata reads for a validated account and the fixed card filename. Preview responses include localized profile, enabled repositories and confirmed claims, canonical character, and cards. Duplicate work for the same revision and selected model pair is idempotent; conflicting work is rejected. One embedding reindex owner runs at a time, using the existing cancellation, verification, provider transition and last-known-good machinery. Process interruption becomes a recoverable failed job, never successful activation.

Preparation uses anonymous, bounded GitHub reads for selected public repositories. Existing vectors are reused for unchanged passages; source commits and citations are rebuilt from actual fetched snapshots. Character-only changes may reassemble the bundle but must not recompute unchanged passage vectors. Explicit prepare/update never dispatches a workflow. Verification includes checksums, schema, model identity, database integrity and query smoke before atomic activation. Lexical smoke derives its query from the index itself; no project must contain a fixture word such as `retrieval`. Retained bundles use the same content-independent check on restart. Failed/cancelled updates leave active/previous untouched. Query embeddings remain necessary for new questions.

Local owner assertions use the reserved `local/portfolio` namespace and a content-derived 40-hex revision identifier, explicitly tagged `origin=local` in evidence metadata. That identifier is not a Git commit. Their citation URL is constructed by the backend as `/api/public/owner-statements/{revision}/{evidence_id}` and returns only the matching currently active confirmed assertion as plain text. Stale revisions return 404. Repository facts retain real immutable GitHub commit/line links. Neither a model nor repository content may choose citation URLs.

Explicit local preparation durably disables Release polling before work is queued, preventing a competing remote writer even if that build fails. Existing active/previous bundles are retained. Advanced rollback continues through existing bundle controls; restoring legacy transport is an explicit operator configuration change and requires stopping the service and removing the local-source marker after backing up state. No simultaneous publication owners.

## Sharing

The product offers a bilingual three-stage guide: find/create the public same-name profile repo and root README; download/upload one `reponpc-card.gif` at its root; copy the actual relative-image Markdown into the existing README, preview, save and test the profile card. Use actual default-branch metadata, never assume `main`. Read failures are not proof of nonexistence; missing and unavailable remain distinct. Root image status and external NPC availability are independent. Public metadata checks are read-only and accept validated GitHub account/file inputs only.

The share target must be an absolute public HTTPS visitor URL without credentials or fragments; loopback, private IP and local hostnames are rejected. No server fetch to arbitrary supplied URLs. URL validation does not claim external reachability. Public sharing requires an operator-managed HTTPS reverse proxy that allows visitor routes only; admin and model services stay private. The Windows launcher remains a loopback evaluation entry point. No tunnel, hosted service, purchase or GitHub write is implicit in this amendment. External verification remains an explicit real-browser test at a supplied actual public destination.

## Acceptance mapping

FR-006/012/015–025/028/033/039–042 and AC-020–032/034–040/046/049/053/055–061 apply with GitHub-only transport replaced by this local primary path. Required evidence: local save/reload/conflict; canonical character applied in configuration/card; no-token preview/build/activation; zero repeat passage calls for unchanged input; cancellation/failure rollback; restart recovery; safe local assertion citations; bilingual guide unknown/missing/ready states and non-main branches; browser download and visitor trial. Actual public GitHub/HTTPS testing must be reported separately from local and automated checks.

## Current delivery boundary (2026-09-23)

Browser acceptance found that the frontend's history ceiling could exceed the operator's configured chat limits. The existing `PAYLOAD_TOO_LARGE` error envelope now reports numeric admission bounds inside its extensible `details` object (`max_message_characters`, `max_history_messages`, `max_history_characters`). No acceptance threshold changes. The visitor client may retry once after a pre-provider 413, using a recent suffix of whole successful exchanges within those bounds and its original hard ceilings. It preserves the displayed transcript, never shortens the current question, and does not retry malformed limits, cancellation, unrelated errors, or a second rejection.

The owner has no public HTTPS URL and explicitly requested completing local use and retaining share settings. External deployment, GitHub mutations, and actual external Profile-to-NPC validation are outside this delivery. Safe share fields persist for the current browser session; only a validated public HTTPS URL and normalized account are retained. No example URL is treated as a working destination.
