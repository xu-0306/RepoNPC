## 根因與檢查方式

原先 `.guided-onboarding__step label` 一律使用單欄 grid，直接包住 checkbox 與文字時會分成兩行。「移除金鑰」另有局部樣式，沒有覆蓋新增的「更換服務網址」。`select` 又未列入全域字型繼承規則，實測為 13.333px，而鄰近標籤為 18px。

先前檢查偏重元件輸出、預設畫面和一般尺寸，沒有完整展開服務編輯表單、放大文字並量測實際排版，因此漏掉這類錯誤。本輪使用正式 React 元件與 CSS 的隔離頁，加入展開狀態、長文字、雙語、窄欄和事件順序檢查。SSR 測試只能驗證語意結構，不能代替瀏覽器排版。

Luna max 以唯讀方式檢查事件路徑；Main 負責全部本輪實作、共享狀態整合與瀏覽器反證。未接受子代理的程式修改。代理提出但無法重現的「第二個貢獻面板輸入後自動收起」已排除：React 不會在相同 `open` prop 的普通重繪中反覆覆寫使用者展開狀態，實際輸入後仍保持展開。

## 已修復的資料與事件順序

| 觸發方式                               | 修復與驗證                                                                                                                                           |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 先勾「移除金鑰」，再填新金鑰           | 新輸入取消移除勾選；反過來勾移除會清空新輸入，避免最後輸入被靜默忽略。                                                                               |
| 變更連線方式或切換更換網址             | 清除前一操作的金鑰／移除意圖；改連線方式時必須提供對應的新網址，不能取消替換而保留舊協定網址。                                                       |
| 儲存中再次提交或關閉編輯器             | 提交入口增加 pending 防護；實際事件檢查確認一次請求、控制項停用、編輯器保持開啟。失敗時保留可重試的表單，金鑰依既有規則清空；成功後關閉並恢復焦點。  |
| GitHub 帳號 A 已到最後頁，再改成帳號 B | reducer 重設探索頁數和「還有下一頁」狀態；保留已收集／選取專案與貢獻資料。頁數由 reducer 統一管理，返回此步驟也不會因元件區域變數遺失而重讀第 1 頁。 |
| 已讀取 Ollama 模型清單後，服務版本變更 | 清單綁定服務 ID 與 revision；重新整理發現版本變更、服務移除或改協定時清除清單並作廢舊請求。延遲回應不能重新帶回舊服務的模型，明確重讀可取得新清單。  |
| 顯示 YAML 預覽後繼續編輯               | 同時清除驗證結果及舊預覽，避免舊內容仍標為目前草稿。                                                                                                 |
| 訪客點選建議問題                       | 填入文字並把焦點移到問題輸入框，可直接繼續輸入或送出。                                                                                               |

模型／服務增刪改、測試、選用、表單取消與 pending、導覽／專案選取、貢獻編輯、草稿驗證／預覽、訪客提問的事件路徑均納入程式檢查；動態測試範圍以下列證據為準。後端發布、分析任務、真實模型計費操作未在本輪重新實際執行。

## 留給擁有者的設計選擇

1. **減少重複標題與說明。** 目前區塊標題、展開入口、表單標題多次重複「新增模型／編輯 AI 服務」。建議保留清楚的操作入口，展開後只放欄位和一段必要說明；長篇技術解釋移到「更多說明」。這需要調整資訊層級，不只是修錯位。
2. **共用服務只管理一次。** 同一 AI 服務目前在回答／查找兩區都能編輯，新手可能誤以為必須建立兩份。建議設獨立共用服務區，兩種模型各自選用服務；若保留現版，至少明示「這個服務可供兩種模型共用」。
3. **技術細節的閱讀層級。** 展開區仍有 `Ollama host`、`probe`、維度和較小的輔助字體。建議主文統一使用「服務」「測試」，保留產品名稱；原始技術詞放說明內，輔助文字採一致的較大字級。服務商錯誤維持原文，不再按 HTTP 狀態推測原因。

修復本身沒有等待上述選擇；這些是後續整體簡化的方向，不列為本輪已完成的設計。
